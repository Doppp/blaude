Most people will read your post on a phone, in a queue, with one thumb. That is not a reason to write less. It is a reason to put the answer first and let the detail follow.

## Start with the answer

Open with the sentence a busy reader needs, then earn the rest. If someone stops after the first paragraph, they should still leave with the point.

A good test: read only your *first sentence* of each section aloud. Does it still make sense as a summary? If it does, the structure is doing its job.

## Keep paragraphs short

On a 360 px screen a long paragraph becomes a wall. Three or four sentences is plenty. Break where the thought turns, not where the line ends.

- One idea per paragraph.
- Lists for things a reader will scan.
- Headings every few screens, written as statements.

When order matters, number it:

1. Write the draft the way you would say it.
2. Cut the first paragraph if it only warms up.
3. Read it on your phone before you share it.

## Tables are fine, if they're small

| Width | Characters per line | Feels like |
| --- | ---: | --- |
| 360 px | about 40 | A paperback, held close |
| 768 px | about 70 | A printed page |
| 1280 px | 70, capped | The same page, more margin |

> The column stays the same width on a laptop. The page just gets more air.

## Links and code

Plain links like [the Web Content Accessibility Guidelines](https://www.w3.org/WAI/standards-guidelines/wcag/) wrap like any other text. So does inline code such as `max-width: 680px` or a long address like https://example.com/a/very/long/path/that/keeps/going/and/going/without/a/break.

That's the whole method. Write the way you talk, then read it where your readers will.
